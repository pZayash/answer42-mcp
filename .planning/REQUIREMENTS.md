# Requirements — 1C Test Client MCP

## v1 Requirements

### MCP server
- [ ] **MCP-01**: Агент может запустить MCP-сервер через stdio.
- [ ] **MCP-02**: MCP-сервер публикует WebSocket URL для подключения обработки 1С.
- [ ] **MCP-03**: MCP-сервер коррелирует команды и ответы по request id.

### 1C bridge
- [ ] **BRIDGE-01**: В репозитории есть исходники внешней обработки `MCPTestManager`.
- [ ] **BRIDGE-02**: Обработка читает URL WebSocket из `/C` и подключается к серверу.
- [ ] **BRIDGE-03**: Обработка принимает JSON-команды и возвращает JSON-ответы.

### Test client control
- [ ] **TEST-01**: MCP-команда подключает тестируемую базу как клиент тестирования.
- [ ] **TEST-02**: Поддержан тестовый стенд `<TARGET_INFOBASE_URL>` с `<USERNAME>/<PASSWORD>`.
- [ ] **TEST-03**: MCP-команда разрывает соединение с тестируемым приложением.

### UI introspection
- [ ] **UI-01**: MCP-команда возвращает активное окно.
- [ ] **UI-02**: MCP-команда возвращает дерево UI-объектов с базовыми свойствами.
- [ ] **UI-03**: MCP-команда возвращает командный интерфейс/панель, если API 1С его предоставляет.

### Actions and screenshots
- [ ] **ACT-01**: MCP-команда нажимает кнопку по имени или заголовку.
- [ ] **SHOT-01**: MCP-команда сохраняет скриншот экрана и возвращает путь/base64.

### Documentation
- [ ] **DOC-01**: README описывает установку, запуск и пример использования.
- [ ] **DOC-02**: Архитектура описана отдельным документом.

## Deferred / v2

- Запись и воспроизведение сценариев тестирования.
- Управление несколькими тест-клиентами одновременно.
- Богатая типизация всех видов тестируемых элементов.
- Автоматическое создание/загрузка пустой служебной базы через автономный сервер.
