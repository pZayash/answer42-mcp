# 1C Test Client MCP

## What This Is

MCP-сервер для управления приложением 1С:Предприятие через режим менеджера/клиента тестирования.

Проект должен позволить LLM/агенту через MCP подключаться к тестируемой базе 1С, получать состояние интерфейса, командных панелей и форм, выполнять базовые действия и снимать скриншоты.

## Why

Сейчас автоматизация 1С через агентные инструменты упирается в отсутствие транспорта между внешним MCP-клиентом и встроенным языком 1С в режиме менеджера тестирования. Нужен прототип, который:

- запускается как обычный MCP-сервер;
- поднимает WebSocket-транспорт для обработки 1С;
- стартует пустую/служебную информационную базу в режиме менеджера тестирования;
- загружает обработку 1С, которая подключается к MCP-транспорту;
- через тест-клиент управляет существующей информационной базой.

## Target Architecture

1. MCP-сервер — Python-скрипт.
2. MCP-сервер поднимает WebSocket-сервер для связи с 1С.
3. Обработка 1С запускается в пустой информационной базе через автономный сервер/платформу 1С в режиме менеджера тестирования.
4. В обработку через `/C` передаются параметры подключения к WebSocket-серверу.
5. Обработка подключается к WebSocket-серверу, получает команды и возвращает ответы.
6. Команда MCP подключает тестируемую базу как клиент тестирования. Тестовый стенд: `<TARGET_INFOBASE_URL>`, логин `<USERNAME>`, пароль `<PASSWORD>`.
7. После подключения доступны команды интроспекции UI и управления:
   - состояние активного окна;
   - список верхнеуровневых объектов;
   - дерево формы/элементов;
   - командные панели;
   - выполнение команд/нажатие кнопок;
   - скриншот экрана.

## Constraints

- Язык MCP-сервера: Python или JS. Для первого прототипа выбран Python.
- Связь MCP ↔ 1С: WebSocket.
- Код 1С должен использовать API режима тестирования (`ТестируемоеПриложение`) и WebSocket API платформы.
- Для справки по синтаксису 1С использовать MCP `bsl-context`.
- Для работы с обработками 1С использовать локальные 1С skills (`epf-init`, `epf-build`, `db-*`) там, где возможно.
- В первом прототипе допускаются платформозависимые команды запуска 1С; они должны быть явно вынесены в конфиг/аргументы.

### Out of Scope

- Полное покрытие всех типов тестируемых объектов 1С — первый этап делает универсальную сериализацию доступных базовых свойств.
- Полноценная IDE/record-playback система тестов — это отдельный слой над MCP.
- Стабильная кроссплатформенная сборка EPF в CI — пока достаточно исходников и локальной команды сборки.
- Обход ограничений безопасности 1С/ОС для снятия скриншотов — скриншоты делаются доступными системными средствами.
