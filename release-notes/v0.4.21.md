# Answer42 v0.4.21

Post-action diagnostics release for interactive 1C UI automation.

## Added

- Added stable post-action diagnostics flags to `client_diagnostics`: `has_user_messages`, `has_validation_messages`, `has_error_info`, `has_dialog`, `modal_opened`, `modal_looks_like_dialog`, `active_window_title`, `active_form_name`, and `active_window_changed`.
- Added normalized `client_diagnostics.events[]` entries for `user_messages`, `validation_messages`, `error_info`, `active_window_changed`, and `dialog` so tool callers can react to 1C UI events immediately after any interactive action.
- Captured active window title and active form name before each manager command and compare them with post-action state.

## Changed

- Generic post-action diagnostics now reports opened modal/dialog windows with title/form/text/buttons/is-error details and no longer auto-closes single-button dialogs in that path. Callers decide which button to press.

## Validation

- Unit/protocol checks: `tests/test_protocol.py tests/test_server_tools.py` passed (`87 passed`).
- Full pytest passed (`123 passed, 3 warnings`).
- Focused ruff on changed Python files passed.
- Live smoke on a private BP area confirmed immediate diagnostics for user messages and modal dialogs after interactive actions.
