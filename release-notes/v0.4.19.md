# Answer42 v0.4.19

Performance and diagnostics iteration for slow 1C UI operations.

## Changed

- Added manager-side progress events for long-running UI commands (`ui_tree`, `find_object`, `search_objects`, `click_button`).
- Bridge timeout errors now include the latest progress phase when the manager reported one before the timeout.
- Added method-specific timeout environment variables for slow UI operations:
  - `ONEC_MCP_CLICK_BUTTON_TIMEOUT`
  - `ONEC_MCP_UI_TREE_TIMEOUT`
  - `ONEC_MCP_FIND_OBJECT_TIMEOUT`
  - `ONEC_MCP_SEARCH_OBJECTS_TIMEOUT`
- Added manager-side search statistics to `find_object` and `search_objects` results.
- Added a platform fast path for `find_object`, with DFS fallback preserved.
- Added cached property/children helpers for manager-side DFS traversal.
- Made `search_objects` use shallow object serialization by default, avoiding unnecessary child-tree expansion for every match.
- Added an internal `include_command_panels` knob for `ui_tree`; existing public tool behavior remains unchanged.
- Reduced duplicated current-page serialization by exposing `current_page_name` and serializing `current_page` shallowly.
- Added Python-side post-filtering for `find_object` and `search_objects` results to guard against stale or buggy manager-side filtering.

## Fixed

- Fixed `search_objects(title=...)`/`find_object(title=...)` matching logic so title filters are applied as normalized substring filters instead of being ignored in some 1C runtime contexts.

## Compatibility

- Public MCP tool signatures are unchanged.
- Manager protocol version remains `2026.08.09.6`; the new progress event fields are backward-compatible.
