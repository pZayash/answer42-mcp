# Answer42 v0.3.5

## Highlights

- Added `--tool-profile` / `ONEC_MCP_TOOL_PROFILE` to reduce MCP tool schema token usage by exposing only scenario-specific tool groups.
- Added automatic cleanup of generated RAG Designer XML dump directories after successful index build.
- Compacted generated dump cleanup results to return counts and paths instead of full source rows.

## Tool profiles

Supported profiles and groups:

- `core` — compact UI set for sessions, windows, forms, fields, tables, tabular documents and screenshots.
- `ui` — full UI set with recording.
- `sessions`, `windows`, `forms`, `tables`, `tabular`, `dynamic`, `rag`, `recording` — atomic groups.
- `full` / `all` — backward-compatible full tool catalog.

Profiles can be combined, for example `core,rag` or `core,dynamic`.

Measured local tool-schema payload sizes:

| profile | tools | schema chars |
| --- | ---: | ---: |
| `full` | 122 | 78 508 |
| `core` | 62 | 38 601 |
| `core,rag` | 77 | 51 983 |
| `ui` | 97 | 57 469 |
| `sessions` | 10 | 6 348 |
| `rag` | 15 | 13 382 |

## RAG cleanup

`rag_session_autoconfigure` now has `cleanup_generated_sources=true` by default. After a successful `build_index`, generated XML source dumps under `dump_root` are removed because the SQLite RAG index is self-contained. Pass `cleanup_generated_sources=false` when you need to inspect or reuse the XML dump tree.
