# Answer42 v0.5.10

## Changes
- Список инструментов: описания параметров из `Annotated[..., "..."]` теперь публикуются (было 0 из 463); без служебных `title` и плавающего `default-<pid>` у `session_id`; без пустых `outputSchema`, из-за которых ответ уходил дважды; сокращены самые длинные описания.
- Ответы: JSON без отступов, `client_diagnostics` без пустых полей и дублей, узлы интерфейса без значений по умолчанию. `windows_list`, `active_window`, `activate_window`, `goto_*`, `wait_*` возвращают `children_count` вместо поддерева (`include_children=true` — полное дерево): `windows_list` 119k → <1k символов.
- Исправлены инструменты, которые не работали: `set_file_dialog_result` (неверная сигнатура платформенного метода), `get_object` (запись в реквизит формы), `goto_*` (вне главного окна), `set_form_fields`/`table_set_row_values` с пробелами в именах полей.
- `set_form_fields` ставит поля по одному через `set_field_value` с проверкой и отчётом по каждому полю.
- Честные результаты: `wait_form_closed` сообщает timeout, `save_form` проверяет, что форма перестала быть изменённой, `close_form` на начальной странице — `nothing_to_close`, проверка `set_field_value` не принимает «100» за «10».
- Табличные и групповые команды ищут элемент своего типа, а не окно; `table_rows` не сдвигает текущую строку; `table_move_row` сообщает, где остановился; `table_end_edit` без редактирования — не ошибка.
- `watchdog_timeout=0` отключает watchdog; Python ждёт мост не меньше собственного `timeout`/`wait_seconds` команды.
- Стабильность: тяжёлые шаги `start_session` вне цикла событий; при сбросе сессии освобождается общий ibsrv; `tabular_document_save` удаляет файлы-пробы; порт ищется за пределами полосы, если она зарезервирована Windows.
