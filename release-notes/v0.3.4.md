# Answer42 v0.3.4

## RAG: Designer XML CommonForms + form element indexing

- Fixed CommonForms in designer_xml format: `_extract_common_form()` now uses `_find_form_file()` which correctly resolves `Ext/Form.xml` (the path used by Configurator dumps), instead of only looking for `Form.form`/`Form.xml` directly in the object directory.
- Added `Constants` and `CommonForms` to `KIND_DIRS` so both EDT and designer_xml parsers discover them.
- Added `_form_data_path()` helper to handle nested `<dataPath>` elements with `<segments>` children (common in Configurator dumps).
- Added `extendedtooltip` and `contextmenu` to form element tag filter.
- Added `title` attribute extraction for form elements.
- Added per-element FTS/embedding chunks for attributes, forms, and form elements (previously only object-level chunks were indexed).
- Verified on real BP 27932 Configurator dump: 744 constants, 434 common forms, 21 625 common form elements indexed and searchable.
