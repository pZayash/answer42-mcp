# Answer42 v0.4.74

## Fixes
- Make `set_field_value` honest in the 1C web client: successful input is now confirmed against persisted field data instead of temporary editor text.
- Add Python-side post-verification for `set_field_value`, including empty-string clears, and downgrade unpersisted values to `set=false` with diagnostics.
- Tighten form field lookup when `search_by_title=true` so title searches do not match surrounding groups instead of real form fields.
- Require confirmation for direct choice/list/menu fallback paths and for selection forms; `choose_current_row`/field selection no longer report success unless the selection actually closes or returns to the caller form.
- Improve empty-value clearing with strict confirmation and controlled failures when a clear does not persist.
- Improve table row matching by using user-visible row text rather than JSON-escaped data, including nested row value structures and AND semantics for structured `row` specs.
- Stabilize `table_set_field` row restoration and verification for reference columns with and without `row`, including create-if-missing fallback behavior.
- Fix table checkbox handling for classifier forms such as OKEI, including row-positioned and current-row toggles and fallback verification for unmark actions.
- Do not treat form-closing commands such as save/post-and-close as confirmed when the form remains open.
- Bump MCP test manager protocol to `2026.09.01.20` and rebuild the bundled `MCPTestManager.cf`.
