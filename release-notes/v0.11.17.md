# Answer42 v0.11.17

## Изменения
- **`table_add_row` для таблиц с отдельной формой строки.** Если добавление строки открывает форму («Основные средства» во вводе начальных остатков), вызов раньше искал кнопку «Добавить» около 14 секунд и падал с ошибкой «bridge_error». Теперь он за несколько секунд отвечает `added: true`, `method: api_add_row_opens_form`, `row_form_opened: true` и заголовком открытого окна. Форму строки дальше заполняют через `set_field_value`.
- **`set_field_value`: значения нет в списке выбора.** Текст ошибки перечисляет варианты открытого списка (до 15), например: «Доступные варианты: Начисление амортизации; Стоимость не погашается; …».
- **Булев отбор в `dynamic_list_set_settings`.** Отбор `{"field": "Проведен", "value": "Да"}` не ставился: ячейка значения в таблице отбора для булева поля не принимает ввод. Если ячейка не приняла значение, оно вводится в поле быстрого отбора с тем же заголовком (режим «Быстрый доступ»).

## Совместимость
- Новых инструментов и параметров нет, прежние вызовы работают как раньше. Для таблиц с формой строки ответ `table_add_row` содержит новые поля.
- Изменён модуль менеджера (`MCPTestManager.cf` пересобирается автоматически из исходников).

## Проверка
- Локально на Windows: pytest, ruff, py_compile, `git diff --check`, сборка пакета и `twine check`.
- Вживую: тестовая база Бухгалтерии, ввод начальных остатков (форма строки основного средства: дата, число, строка, перечисление, флажок, ссылка, отсутствующее значение), отбор «Проведен» = «Да» и «Нет» в списке «Поступление товаров и услуг».
- Не проверялось: Linux, интерфейс на английском, булев отбор без режима «Быстрый доступ».

## Не менялось
- Если поле отбора названо неточно («Сумма документа» вместо «Сумма»), ошибка не подсказывает похожие названия.
