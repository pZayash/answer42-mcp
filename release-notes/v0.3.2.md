# Answer42 v0.3.2

## Highlights
- Added RAG autoconfigure support for dumping all live infobase extensions via Designer `DumpConfigToFiles ... -AllExtensions`.
- Added separate `dump_username` / `dump_password` parameters for direct Designer dump connections that use different credentials than the web/test-client session.
- Ignored service/fresh patch extensions named `EF_*` in RAG source registration and snapshots while keeping diagnostics about skipped dumps.
- Fixed strict dynamic-list settings tools on the 1C 8.5/Linux UI: available fields are read from the correct settings page, and `dynamic_list_set_settings` no longer waits excessively on dropdown formation.
- Hardened the autonomous E2E harness for the current dynamic-list MCP tool names and strict output/settings assertions.

## Changes
- Add `dump_all_extensions_to_xml(...)` and integrate Designer `-AllExtensions` into `rag_session_autoconfigure`.
- Register non-`EF_*` Designer extension dumps as generated RAG extension sources and include them in snapshots.
- Filter `EF_*` extensions from runtime/catalog extension lists and Designer dump-derived metadata.
- Mask `dump_password` in autoconfigure logs and document direct dump credential overrides.
- Fix dynamic-list settings element name generation for filter section (`Элемент0` instead of empty suffix).
- Reduce dropdown formation waits in value-setting helpers from 60 seconds to 3 seconds to avoid long modal settings stalls.
- Update dynamic-list E2E checks to verify returned tabular documents and live available fields instead of relying on removed/legacy tool names.
- Rebuild packaged `MCPTestManager.cf` and `MCPTestClient.cf` assets from XML sources.
