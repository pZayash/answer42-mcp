# Answer42 v0.8.0

## Изменения
- **Несовместимое изменение: `html_mode` вместо `html_agent`.** Способ доступа к живым страницам HTML-полей выбирает `start_session(html_mode=...)`; значение по умолчанию — `ONEC_MCP_HTML_MODE` или `auto`. Параметра `html_agent` больше нет: мост почти ничего не стоит, пока не вызван `html_*`, а выключить его можно режимом `disabled`.

  | `html_mode` | Windows | Linux |
  |---|---|---|
  | `auto` (по умолчанию) | `patched`, если в Web Inspector платформы установлен актуальный мост, иначе `console` | `remote` |
  | `console` | горячая клавиша инспектора и загрузчик в его консоли | не поддерживается |
  | `patched` | мост в Web Inspector платформы (`answer42 webkit-inspector install`) | мост подставляется для сессии, ничего устанавливать не нужно |
  | `remote` | — | удалённый отладчик WebKitGTK |
  | `disabled` | мост не запускается | мост не запускается |

  Явно выбранный режим не подменяется другим: недоступный (`patched` без моста в платформе, режим другой ОС) отклоняется до запуска клиента с подсказкой.
- **Linux: режим `patched` без установки и прав администратора.** Интерфейс инспектора WebKitGTK вшит в системную `libwebkit2gtk`, поэтому Answer42 его не меняет: переменная GLib `G_RESOURCE_OVERLAYS` подставляет тест-клиенту из каталога сессии один файл инспектора (`localizedStrings.js`) с мостом. Answer42 ставит фокус в HTML-поле средствами клиента тестирования и открывает инспектор клавишей Ctrl+Alt+Shift+F12 через `xdotool`; интерфейс инспектора подключается сам (~0,8 с), сообщения консоли видны с момента загрузки страницы. Нужен `xdotool`.
- **Linux: `console` отклоняется.** Встроенный инспектор WebKitGTK — не отдельное окно X11, поэтому клавиши уходят в элемент с фокусом, то есть в саму страницу: в проверке загрузчик попал в поле ввода чата и был отправлен как сообщение.
- **Linux: переход во внешний браузер больше не вешает клиент.** 1С открывает ссылки и файлы через `xdg-open` и ждёт его завершения, а `xdg-open` ждёт первый экземпляр браузера: клиент 1С, мост тест-клиента и инструменты `html_*` висели, пока не закроют Chrome (нажатие «Скачать» — таймаут 180 с). Тест-клиент получает обёртку `xdg-open`: она записывает адрес и сразу возвращает управление, а на настоящем дисплее открывает адрес в браузере отдельно от клиента. Записанные адреса — в `external_opens` ответов `html_field_click_link` и `session_status`. `ONEC_MCP_EXTERNAL_OPEN`: `auto` (на собственном Xvfb Answer42 только записывать), `open`, `record`, `off`.
- **Новый инструмент `html_download`** скачивает файл по ссылке живой страницы запросом изнутри страницы (действуют её cookie и сеанс) и сохраняет его в каталог сессии: путь, имя, размер, тип, HTTP-статус, `sha256`; ответ 4xx/5xx — ошибка. Проверять скачивание отдельным HTTP-запросом больше не нужно.
- **Исправлено: ложная ошибка запуска тест-клиента.** Вывод клиента дописывался в один файл через все запуски, и предупреждение WebKitGTK «Error sending message on socket connection», которое прошлый клиент оставлял при остановке сессии, следующий `start_session` или переподключение с тем же id принимали за ошибку запуска и останавливали исправный клиент. Теперь каждый запуск начинает вывод заново (прошлый сохраняется как `.previous`), а строки журнала GLib/GTK ошибкой запуска не считаются.

## Проверка
- Локально на Windows: pytest, ruff, py_compile, `git diff --check`, сборка пакета и `twine check`, сборка сайта `sphinx -W`.
- Вживую на Windows (демо-обработка, 8.5.1.1343): `auto` на пропатченной платформе выбирает `patched` (1,48 с), явный `console` — 2,33 с.
- Вживую на Linux (Debian 13, 8.5.1.1343, WebKitGTK 2.36, Xvfb) на чате «НейроСотрудник» тестовой базы: `patched` — 0,8 с, `html_text`/`html_query`/`html_console`; `console` отклоняется, `disabled` запускается без моста; нажатие «Скачать» средствами 1С — 0,45 с вместо таймаута 180 с, адрес в `external_opens`; `html_download` сохранил PDF (48 335 байт, HTTP 200); четыре вопроса нейросотруднику без сбоев клиента.
- GitLab CI запускает модульные тесты и проверки пакета в пайплайнах веток и тегов; публикацию в PyPI и создание GitLab Release выполняет пайплайн тега.
