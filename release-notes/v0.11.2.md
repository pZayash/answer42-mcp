# Answer42 v0.11.2

## Изменения
- **Браузерный клиент: ключи адреса.** Параметры в адресе базы (`?N=…&P=…&OIDA-`: вход по имени и паролю, отключение SSO) теперь доходят до браузера; раньше `start_session(client_mode="browser")` их отбрасывал.
- **Удалённая публикация.** Менеджер тестирования ищет клиент на сервере своей информационной базы и не видит клиента, который зарегистрировался на чужом сервере (например, за nginx, где открыты только 80/443), а потом блокируется на минуты. Для не-локального хоста сопряжение теперь не запускается: `start_session` отвечает за секунды, в `test_client` будут `connected: false`, `attach_error`, `warning` с причиной и `available_tools` (`html_*`, `browser_*`). `ONEC_MCP_BROWSER_FORCE_PAIRING=1` пробует сопряжение всё равно.

## Совместимость
- Локальные публикации и режим `thin` не изменились.
- Формы, таблицы и навигация в браузерном режиме работают только для базы на этой машине; для удалённой публикации доступны DOM-инструменты и скриншоты.

## Проверка
- Локально на Windows: pytest, ruff, py_compile, `git diff --check`, сборка пакета и `twine check`.
- Вживую: локальная база в Apache (Chrome), сопряжение, `open_navigation_link`, `form_state`; удалённая база `dev-area-06` отвечает `connected: false` с пояснением за ~26 с.
- Не проверялось: доступ к тестовым портам удалённого сервера по tailscale (узел был офлайн), Edge, IIS, Linux.
