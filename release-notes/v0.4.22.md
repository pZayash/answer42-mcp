# Answer42 v0.4.22

Dynamic-list stability release for live 1C UI automation.

## Fixed

- `dynamic_list_find` now preserves a pre-search navigation candidate and returns `matched=true` with `match_method=pre_search_navigation_candidate` when the standard 1C search dialog runs but does not leave an API-visible current row.
- `dynamic_list_filter_by_current_value` no longer calls the non-existent `ТестируемаяТаблицаФормы.АктивизироватьЯчейку(...)`; it relies on `ПолучитьТекстЯчейки(<column>)` before invoking the standard context command.
- `dynamic_list_settings_available_fields` no longer serializes the large settings tree row-by-row with `ПолучитьТекущуюСтроку()+ЗначениеВJSON(...)`; it uses lightweight `ПолучитьТекстЯчейки("Доступные поля")` traversal with duplicate protection and a 5000 ms guard to avoid bridge hangs.

## Validation

- Focused protocol/server tests passed.
- Full pytest passed.
- Focused ruff passed.
- Live smoke on a private BP area confirmed:
  - `dynamic_list_find(text="<DOCUMENT_NUMBER>", field="Номер")` -> `matched=true`.
  - `dynamic_list_filter_by_current_value(cell="Номер", text="<DOCUMENT_NUMBER>")` -> `filtered=true`, `errors=[]`.
  - `dynamic_list_settings_available_fields(section="filter", limit=30)` -> `found=true`, `count=30`, `timeout=false`, `errors=[]`.
