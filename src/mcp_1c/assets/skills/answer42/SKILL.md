# Answer42

Используй этот скилл для живой работы с интерфейсом 1С через MCP Answer42: открыть сессию, пройти управляемые формы, заполнить поля/таблицы, сформировать отчёт, получить структурные данные или evidence.

## Главный принцип

Работай через first-class tools Answer42, а не через X11/WinAPI/ручные клики. Скриншот — evidence и диагностика, не источник табличных данных; для данных используй структурные tools (`field_value_text`, `table_rows`, `tabular_document_text/save`, `dynamic_list_output`).

## Запуск и завершение

1. Сначала проверь существующие сессии `sessions_list`; не плодить дубликаты одного стенда.
2. Запускай `start_session(base_url=..., version=...)`. `base_url` — единый target: web URL, `server/infobase` или путь к файловой базе.
3. Креды лучше хранить через `credentials_save`; в задачах не светить секреты и не передавать пароль-заглушку `***` как реальный пароль.
4. При сбоях запуска смотри `session_status`, diagnostics из tool-response, при runtime-ошибках — `export_eventlog`.
5. По завершении задачи останавливай сессию `stop_session`, если она больше не нужна.

## Навигация и диагностика формы

- Открывай объекты явными `e1cib/...` ссылками через `open_navigation_link`; не передавай туда имена команд формы.
- Для поиска элемента используй `search_objects`/`find_object`; для понимания формы — `ui_tree(profile="navigation")`.
- На больших формах используй `ui_tree(delivery="resource")` и затем `ui_tree_resource_search/get_node/children`; не загружай полный resource в контекст без нужды.
- Не включай `include_data=true` по всей форме без причины: для значений есть точечные tools.
- После значимых действий проверяй пользовательские сообщения, модальные окна и `current_error_info`. Не считай действие успешным без структурного подтверждения или evidence.
- Если элемент на неактивной странице, сначала активируй страницу/группу, потом взаимодействуй с элементом.

## Подсказки форм (form hints)

Answer42 может показывать discovery-блоки с именами доступных операций, без текста подсказок:

- `start_session` → `global_hints`, `startup_hints`;
- `ui_tree` → `form_hints` для текущей формы и текущего scope, без глобальных подсказок;
- `configuration_name_version_from_subsystems` → `configuration_hints`;
- `installed_extensions_from_catalog` → `extension_hints`.

Если discovery показывает подходящую операцию — прочитай её через `form_hints_get(operation=...)` до импровизации. Особенно проверяй hints, когда:

- документ не сохраняется/не проводится из-за обязательного поля;
- появилось сообщение о незаполненном реквизите;
- имя поля/таблицы отличается от ожидаемого;
- стало понятно, что выбран неправильный UI-путь.

### Как сохранять hints

- `scope="base"` — если подсказка зависит от данных, состояния или настроек конкретной информационной базы: заведённые организации, права, включённые функциональные опции, варианты отчётов, пользовательские настройки.
- `scope="configuration"` — если это принцип работы конкретной конфигурации независимо от базы: где находится реквизит в типовой форме, какая вкладка нужна, какая таблица используется в документе. Не указывай версию конфигурации для таких hints.
- `scope="extension"` — если поведение внесено расширением и полезно там, где оно установлено.
- `scope="global"` — если это общий принцип управляемого интерфейса 1С или стандартный элемент/паттерн, который не привязан к конкретной базе, конфигурации или расширению.

## Динамические списки и таблицы

- Для динамического списка сначала пойми структуру через `ui_tree`/`table_current_row`, потом применяй поиск, настройки или вывод списка.
- Для больших списков избегай полного чтения строк без лимита; предпочитай поиск/позиционирование/текущую строку.
- Для ссылочных полей предпочитай стандартные формы выбора 1С; для выпадающих списков сначала смотри доступные значения и устанавливай видимое представление.
- Настройку вложенных колонок через «Изменить форму» считай ненадёжной: кнопки добавления полей могут быть видны, но недоступны через test-client API. Для проверяемых сценариев фильтрации используй настройки списка/компоновщика.

## Отчёты и табличные документы

- Для отчётов проверяй результат через `tabular_document_text` или сохранённый файл, а не по скриншоту.
- Для больших экспортов ставь достаточный watchdog; если клиент заблокирован — сначала `client_busy_status`/`wait_client_idle`, затем продолжай.
- Перед финальным ответом проверь существование и формат сохранённого файла: PDF начинается с `%PDF`, XLSX открывается как ZIP.

## Evidence

Для демонстрационного сценария включай `recording_start` и закрывай `recording_stop`. В финале указывай реальные артефакты (`MEDIA:<path>`) и честно описывай блокер, если живой клиент не дошёл до результата.

## Разработка Answer42

Если задача про изменение самого Answer42, это уже engineering-режим, не обычная UI automation:

- сначала читай `AGENTS.md` репозитория;
- запускай проверки через `.venv`;
- перед релизом проверяй unit tests, lint, `py_compile`, build/twine check и релевантный live smoke;
- bundled skills хранятся только в `src/mcp_1c/assets/skills/*`.
