# Answer42: Универсальный отчёт 1С

Используй этот скилл, когда задача — сформировать или экспортировать **Универсальный отчёт** в живой базе 1С через MCP Answer42.

## Preconditions

1. Подтверди точный URL информационной базы у пользователя. Не переключайся молча между beta/prod публикациями.
2. Проверь, что для URL есть credentials:
   - `Answer42-full__credentials_check(base_url=...)`;
   - если пользователь явно дал креды, сохрани их через `Answer42-full__credentials_save`;
   - в `TOOLS.md` записывай только назначение/указатель, не раскрывай пароль в публичных ответах.
3. Запускай свежую Answer42-сессию с понятным `session_id` под конкретную задачу.
4. Если только что менялся MCP manager / BSL / CF, перезапусти сессию: уже открытые формы 1С держат старый код.

## Открытие отчёта

Открывай стандартный универсальный отчёт навигационной ссылкой:

```text
Answer42-full__open_navigation_link(
  navigation_link="e1cib/app/Отчет.УниверсальныйОтчет",
  session_id=<session>
)
```

Ожидаемая форма после выбора источника или при уже сохранённых настройках:

- окно: `Универсальный отчет: ...`;
- форма: `ОбщаяФорма.ФормаОтчета`;
- табличный документ обычно называется `ОтчетТабличныйДокумент`.

## Выбор объекта отчёта

Если доступны быстрые настройки компоновщика:

- `КомпоновщикНастроекПользовательскиеНастройкиЭлемент0Значение` — тип объекта, например `Справочники`;
- `КомпоновщикНастроекПользовательскиеНастройкиЭлемент1Значение` — имя объекта, например `Идентификаторы объектов метаданных` или `ИдентификаторыОбъектовМетаданных`.

После выбора нажми `СформироватьОтчет` и дождись появления/готовности `ОтчетТабличныйДокумент`.

## Настройка полей и сортировок

Открывай полные настройки отчёта кнопкой `ВсеНастройки` / `Настройки...`.

Live-proven детали:

- форма настроек: `ОбщаяФорма.ФормаНастроекОтчета`;
- таблица выбранных полей: `ВыбранныеПоля`;
- флаг использования поля: `ВыбранныеПоляИспользование`;
- команда применить и сформировать: `ЗакрытьИСформировать`.

Для задачи вроде “сними все флажки кроме нужных полей”:

1. Открой настройки.
2. Перейди на вкладку **Поля и сортировки**, если она не активна.
3. Прочитай строки `Answer42-full__table_rows(name="ВыбранныеПоля")`.
4. Для каждой строки, которой нет в списке нужных полей, сними `ВыбранныеПоляИспользование` (`Нет` / false).
5. Оставь включёнными только явно нужные поля.
6. Повторно прочитай `ВыбранныеПоля` и проверь точное состояние перед формированием.
7. Нажми `ЗакрытьИСформировать`.

Не угадывай нужные поля. Если пользователь их не указал и нет однозначного предыдущего контекста — задай один короткий уточняющий вопрос.

## Проверка сформированного результата

Предпочитай структурные tools, а не скриншот как источник данных:

```text
Answer42-full__tabular_document_text(
  name="ОтчетТабличныйДокумент",
  row_start=1,
  max_rows=5,
  max_columns=5,
  session_id=<session>
)
```

Проверь:

- `found: true`;
- dimensions (`rows`, `columns`);
- ожидаемое число колонок и видимые заголовки/параметры.

Скриншот можно приложить как evidence для пользователя, но данные отчёта проверяй структурными tools.

## Сохранение / экспорт отчёта

Используй `Answer42-full__tabular_document_save` на `ОтчетТабличныйДокумент`.

Рекомендуемый порядок:

1. XLSX — если пользователю нужны данные.
2. PDF — если нужен визуальный артефакт отчёта.
3. Для больших отчётов ставь достаточно длинный `watchdog_timeout`.

```text
Answer42-full__tabular_document_save(
  name="ОтчетТабличныйДокумент",
  path="build/reports/<report>.xlsx",
  format="xlsx",
  watchdog_timeout=180,
  session_id=<session>
)
```

```text
Answer42-full__tabular_document_save(
  name="ОтчетТабличныйДокумент",
  path="build/reports/<report>.pdf",
  format="pdf",
  watchdog_timeout=180,
  session_id=<session>
)
```

## Gotcha: suffix пути и индекс фильтра

Если файлы попыток выглядят так:

```text
report.pdf_saveas_true_filter1
report.xlsx_saveas_false_filter2
```

и сигнатура файла — `MOXCEL`, суффикс добавлен **после** расширения. 1С сохранила внутренний формат табличного документа, а не PDF/XLSX.

Правильные имена сохраняют расширение последним:

```text
report_saveas_true_filter1.pdf
report_saveas_false_filter2.xlsx
```

Live-proven после фикса 2026-08-20:

- `ЗаписатьСодержимоеВФайл(Истина)` + `filter_index=1` дал валидные XLSX и PDF в проверенном web/thin client;
- валидный XLSX начинается с `PK` и содержит `xl/workbook.xml`;
- валидный PDF начинается с `%PDF`;
- не полагайся навсегда на конкретные номера фильтров: порядок фильтров не является стабильным API 1С;
- пробуй SaveAs `Истина/Ложь` и индексы фильтра, затем выбирай файл по реальной сигнатуре;
- перед каждой попыткой и после неё очищай очередь file dialog result.

## Долгие или заблокированные сохранения

`ЗаписатьСодержимоеВФайл()` может блокировать тонкий/web клиент. Если `tabular_document_save` вернул `interface_blocked`:

1. Проверь `Answer42-full__client_busy_status` или `Answer42-full__wait_client_idle`.
2. Не отправляй новые UI-команды, пока `responsive=false`.
3. Проверь, не появились ли файлы на диске, даже если bridge timeout сработал.
4. Если сессия восстановилась — продолжай. Если нет — останови её с `clean_data=false` и повтори в свежей сессии.

## Что сообщать пользователю

В финальном ответе укажи:

- что настроено: объект, поля, фильтры, сортировки;
- чем проверено: `tabular_document_text`, dimensions/columns, сигнатуры файлов, тесты;
- файлы как `MEDIA:<path>` отдельными строками для OpenClaw/Telegram;
- блокер прямо, если живой клиент 1С не дошёл до результата.

Не утверждай, что отчёт экспортирован, пока файл реально не существует и формат не подтверждён сигнатурой.
