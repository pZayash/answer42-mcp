# Answer42: Универсальный отчёт 1С

Используй этот скилл, когда нужно сформировать, проверить или экспортировать стандартный Универсальный отчёт в живой базе 1С через Answer42.

## Принципы

- Не привязывайся к внутренним именам элементов заранее: состав формы зависит от конфигурации, варианта отчёта и текущих настроек.
- Начинай с `ui_tree(profile="navigation")` и/или `search_objects(title=...)`, затем действуй по видимым labels и структуре формы.
- Если `ui_tree` показывает `form_hints.available=true`, сначала прочитай подходящую подсказку через `form_hints_get(operation=...)`.
- Проверяй результат структурно через `tabular_document_text` или сохранённый XLSX/PDF, а не только скриншотом.

## Типовой workflow

1. Запусти свежую Answer42-сессию с понятным `session_id`.
2. Открой отчёт:
   ```text
   open_navigation_link("e1cib/app/Отчет.УниверсальныйОтчет")
   ```
3. Прочитай форму через `ui_tree(profile="navigation")`.
4. Выбери тип/раздел/объект отчёта по видимым подписям. Если поле ссылочное или списочное — используй стандартный выбор 1С, а не ручной ввод внутреннего значения.
5. Если нужны поля/отборы/сортировки — открой полные настройки (`ВсеНастройки` / `Настройки...`) и сначала прочитай текущие таблицы настроек.
6. После правок перечитай изменённые таблицы и только потом формируй отчёт.
7. Проверь табличный документ, затем сохрани файл, если нужен артефакт.

## Настройки отчёта

- Для выбранных полей найди таблицу выбранных полей, определи колонку использования и меняй только нужные строки.
- Для отборов не удаляй существующие условия без явного указания пользователя. Если пользователь просит “заменить” — отключи/удали старые пользовательские отборы и проверь итог.
- Для сортировок учитывай порядок строк: первая строка обычно имеет больший приоритет.
- Не меняй настройки на неактивных/скрытых страницах вслепую; сначала активируй нужную вкладку и проверь текущие строки.
- Если нужного поля нет в выбранных полях, проверь доступные поля через настройки отчёта/RAG/metadata lookup, а не угадывай техническое имя.

## Проверка и экспорт

- После формирования проверь `ОтчетТабличныйДокумент`: наличие, размеры, заголовки, признаки применённых параметров/отборов/сортировок.
- Для данных предпочитай XLSX; для визуального evidence — PDF.
- После `tabular_document_save` проверь файл на диске: размер > 0, PDF начинается с `%PDF`, XLSX открывается как ZIP.
- Если сохранение заблокировало интерфейс, дождись восстановления через `client_busy_status`/`wait_client_idle`; не отправляй новые UI-команды в заблокированный клиент.

## Когда сохранять hint

Если во время настройки Универсального отчёта нашёл повторяемое знание:

- зависит от данных/варианта/настроек конкретной базы → `form_hints_set(scope="base", ...)`;
- относится к принципу работы отчёта в конкретной конфигурации → `scope="configuration"`, без версии конфигурации;
- вызвано расширением → `scope="extension"`;
- является общим принципом Универсального отчёта или стандартных настроек СКД → `scope="global"`.

Не сохраняй как hint одноразовые значения отчёта, если они не помогут в следующих задачах.

## Финальный ответ

Укажи: объект отчёта, поля/отборы/сортировки, чем проверено, путь к файлам через `MEDIA:<path>`, и явный блокер, если отчёт не сформировался или экспорт не подтверждён.
